# EasyVox Client 5.0.0021-beta (BETA)

**Beta evaluation release, not a final stable release.** [Downloads and SHA-256 checksums](https://github.com/voxistech/easyVoxClient/releases/tag/v5.0.0021-beta).

## Windows: Two Editions

- **Browser** (`-browser.zip`): lightweight package using the machine's maintained modern browser. No WebView2 runtime is bundled, required or downloaded. Both UI launchers open the local browser.
- **Desktop** (`-desktop.zip`): self-contained window with the matching WebView2 runtime included. Useful when no suitable modern local browser is available. Keep the complete extracted folder together.

Both editions provide the same exchange, configuration and console features. Desktop is several hundred MB because it contains a complete browser engine; Browser is only a few MB. The bundled engine is updated through newer Desktop packages, not automatically. Including an engine does not make unsupported operating-system versions compatible.

Each edition is available for Windows x64, ARM64 and x86. The two macOS and four Linux processor variants remain available. Twelve packages and `SHA256SUMS.txt` are attached to this release. There are no installers or uninstallers.

## Changes

- Product version, package names and public presentation use a technology-neutral name.
- Browser-only executables exclude the embedded-window component entirely.
- Package documentation explains the edition choice, download sizes and update responsibilities.
- No automatic permission or ACL changes are performed at startup. Administrator-prepared access may be needed for the embedded engine on some Windows 10 environments.
- Local shutdown tests use isolated connections and consume replies completely, avoiding false timing failures from unused test connections.

## Validation and Limitations

Automated interface and execution checks are performed before packaging. Packages are built for each listed target, but native testing remains required on each operating system and processor.

Local certificate generation does not yet replace V2 account/password authentication. Private keys remain on disk without vault encryption; their protection and backup are the machine administrator's responsibility.

Test with non-production files and back up the saved configuration before evaluating the beta. Third-party legal notices are retained in the packages.
